Implementation Specification

URL Silo Clustering by Shared Keyword Footprint

Specification and prompt to build a modular report that groups related URLs into topical content silos based on shared search queries, overcoming opaque or arbitrary URL structures.

View Raw Execution Prompt Return to Resources Index

1. Examination of Existing Codebase Reports

Prior to designing this report, the current reporting suite was reviewed to assess whether existing modules solve URL siloing:

Existing Report Current Behaviour Limitation for URL Siloing
keyword_cannibalisation_report.py Groups multiple URLs that rank for the exact same query. Only identifies identical-query competition; cannot detect topical clusters where URLs target related but distinct queries.
gsc_pages_queries.py Produces 1-to-many accordions of queries per page or pages per query. Lacks inter-page similarity calculation; does not group collections of related URLs into silos.
library_marketing_migration_analysis.py Uses regex indicator tokens in URLs (e.g. pctm, nuk102) to map to hardcoded marketing folders. Fragile and taxonomy-specific; fails when URLs lack known acronyms or when discovering organic topical silos.
page_level_report.py Aggregates traffic metrics and query counts per URL. Treats each URL in complete isolation; no clustering or semantic relationship detection.
Conclusion: A specialised report is required to calculate pairwise keyword overlap, extract shared topic tokens, and cluster related URLs into cohesive content silos.

2. The Library Challenge & Solution Architecture

On properties such as library.croneri.co.uk, page URLs are frequently arbitrary, numeric, or reference-based (e.g. /cpt-overview-1234, /doc-id-98765). Standard SEO audits that rely on folder hierarchy (e.g. /tax/vat/) fail completely.

The Keyword Footprint Solution

Even when a URL structure is opaque, Google Search Console retains the search query list for which each page receives impressions and clicks. By analysing shared query terms, we can algorithmically reconstruct the topical silo each page belongs to.

Step 1: Tokenisation

Extract Query Footprints

Retrieve ['page', 'query'] performance. Strip punctuation, stop words, and brand terms. Extract 1-gram and 2-gram core topic tokens weighted by impression volume.

Step 2: Similarity Graph

Calculate Inter-Page Overlap

Compute pairwise Jaccard similarity and shared keyword counts across all pages. Group pages sharing high-affinity query portfolios into topical clusters.

Step 3: Silo Synthesis

Assign Silo Leaders & Audits

Identify the Silo Pillar Page (highest traffic page in the cluster). Flag internal cannibalisation and highlight orphan URLs with zero topical neighbours.

3. Proposed Report Specification

Script Location: reports/url_silo_clustering_report.py

Core Deliverables & Silo Metrics

  • Silo Name / Theme: Automatically generated from top connecting keywords (e.g. Silo: VAT Reverse Charge & Construction, Silo: Fire Risk Assessment & Workplace Safety).
  • Silo Pillar / Anchor URL: The page inside the silo capturing the greatest volume of clicks or impressions.
  • Silo Members: List of all associated URLs in the silo, along with their individual traffic stats and primary queries.
  • Connecting Keywords: The shared queries and keywords that bind the URLs together.
  • Internal Silo Cannibalisation: Warnings when two or more URLs in the same silo compete for the exact same search term.
  • Standalone / Unclustered Pages: Tab listing pages with unique query footprints that do not group with any other page.

Output Files

  • CSV: output/<site-url>/url-silo-clustering-<slug>-<start>-to-<end>.csv
  • HTML: output/<site-url>/url-silo-clustering-<slug>-<start>-to-<end>.html

Command-Line Interface

Terminal / Bash 
$python reports/url_silo_clustering_report.py <site-url> --last-month --min-overlap 2 --min-impressions 5 --max-silos 50

4. Copyable Implementation Prompt

Provide the prompt below to your assistant or CLI session to implement the URL Silo Clustering Report.

# Task: Implement URL Silo Clustering Report based on Shared Keyword Footprints

Implement a new modular report in the gsc-exporter codebase: `reports/url_silo_clustering_report.py`.

## 1. Problem Statement & Objective
Websites with non-semantic, arbitrary, or database-generated URLs (such as library.croneri.co.uk) cannot be grouped or siloed using traditional URL path structures.
The objective of this report is to algorithmically group related URLs into topical content silos based on shared search queries and common keywords in their GSC query footprints.

## 2. Review of Existing Codebase
- Existing report `keyword_cannibalisation_report.py` only identifies identical queries ranking across multiple URLs, not topical clusters.
- Existing report `library_marketing_migration_analysis.py` relies on hardcoded acronym lists rather than dynamic clustering.
- Existing report `page_level_report.py` reviews pages in complete isolation.
This new report introduces topical clustering across pages.

## 3. Architecture & Algorithmic Strategy

### A. Data Fetching
- Query GSC performance data using `core.cache.fetch_with_cache` with dimensions `['page', 'query']`.
- Support standard date parameters via `core.date_utils.parse_standard_date_args`.
- Filter out negligible queries using `--min-impressions` (default: 5).

### B. Normalisation & Feature Extraction
1. Clean each query: lowercase, strip punctuation, remove common English stop words, and strip property brand terms using `core.brand.get_brand_terms`.
2. Extract significant n-grams (1-grams and 2-grams) per URL, weighted by impressions or clicks.
3. Build a query footprint dictionary mapping: `page -> Set[query_tokens]`.

### C. Silo Clustering Engine
1. Calculate pairwise similarity between pages using Jaccard similarity of query footprints and shared query counts.
2. Group pages into Topical Silo Clusters using graph connected components or community detection with a configurable `--min-overlap` threshold (default: 2 shared queries/tokens).
3. For each Silo Cluster:
   - Identify Silo Name: The top 2 to 3 most representative shared keywords by impression volume.
   - Designate Pillar Page: The URL with the highest clicks/impressions in the cluster.
   - List Member URLs: All related URLs belonging to the silo with their metrics.
   - Identify Connecting Queries: The common queries binding the pages together.
   - Audit Cannibalisation: Detect pages inside the silo that rank for identical queries.
4. Separate unclustered pages into a dedicated "Standalone Pages" list.

## 4. Deliverables & Outputs

### A. Output Naming
Follow `core.naming` conventions:
- Directory: `output//`
- CSV: `output//url-silo-clustering---to-.csv`
  - Columns: `silo_id`, `silo_name`, `is_pillar_page`, `page`, `clicks`, `impressions`, `ctr`, `average_position`, `shared_keyword_count`, `top_connecting_queries`
- HTML: `output//url-silo-clustering---to-.html`

### B. HTML User Interface (Bootstrap 5)
- Header KPI Tiles: Total Silos Detected, Average Pages per Silo, Clustered URLs Count, Standalone URLs Count.
- Interactive Silo Cards:
  - Header: Silo title, total URLs badge, total clicks and impressions.
  - Body: Pillar page highlighted with a "Pillar Page" badge, expandable table of all member URLs.
  - Collapsible drawer showing shared connecting queries.
  - Cannibalisation warning banner if member URLs compete for the exact same query.
- Tabbed Navigation:
  - Tab 1: Clustered Silos (sorted by total traffic).
  - Tab 2: Standalone / Unclustered URLs (pages with zero topical neighbours).
  - Tab 3: Silo Cannibalisation Summary.
- Search filter to instantly find any URL or keyword across silos.

## 5. CLI Arguments
Standard arguments:
- `site_url`: Target property.
- `--start-date YYYY-MM-DD`
- `--end-date YYYY-MM-DD`
- `--last-month`
- `--last-7-days`
Specialised arguments:
- `--min-overlap`: Minimum shared query/token count to link two URLs (default: 2).
- `--min-impressions`: Minimum impressions threshold for queries (default: 5).
- `--max-silos`: Maximum silos rendered in HTML (default: 50; full dataset in CSV).
- `--exclude-standalone`: Exclude unclustered URLs from report.

## 6. Integration & Testing
- Register in `interactive-runner.py` under "Granular Pages & Queries Audits".
- Register in `utilities/validate_all_reports.py`.
- Add unit test in `tests/test_url_clustering.py` testing pairwise Jaccard calculation and silo grouping logic.

## 7. Standards
- British English throughout (e.g. analyse, prioritisation, categorise, behaviour).
- No em dashes anywhere.
- Hyphenated lowercase filenames.
- Console output explicitly prints generated file paths with clickable `file://` links.
