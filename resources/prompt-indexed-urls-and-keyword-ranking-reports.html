Property Indexation, Keyword Breadth, and Question Ranking Reports

Specification and prompt to build two modular reports analysing URL indexation depth, keyword portfolio distribution (head vs long tail), and question search queries.

View Raw Execution Prompt Return to Resources Index

1. Background and Technical Feasibility

This specification addresses three complementary requirements for Google Search Console (GSC) property intelligence:

Indexed URLs Count

The GSC Search Analytics API surfaces URLs with at least one impression during the queried window. This provides the count of active ranking URLs. In addition, the GSC Sitemaps API can optionally be queried to report submitted vs indexed URL figures from submitted XML sitemaps.

Keyword Breadth

Calculates unique search query counts per page and across the entire property. Segments queries into Head (up to 3 words) and Long Tail (4+ words), as well as impression distribution demand tiers.

Question Queries

Scoped as a dedicated report to isolate and categorise question queries (e.g. What, How, Why, When, Where, Who, Which, Can/Is/Does). Surfaces striking-distance opportunities for editorial optimisation and FAQ enhancement.

2. Report 1: Property Indexation and Keyword Breadth

Script Location: reports/property_indexation_keyword_report.py

Key Metrics and Processing

  • Active Ranking URLs: Unique count of pages receiving impressions via fetch_with_cache with dimensions ['page', 'query'].
  • Property Unique Keywords: Total distinct queries ranking across the entire property (df['query'].nunique()).
  • Keywords per URL: Grouped query breadth (df.groupby('page')['query'].nunique()) alongside clicks, impressions, CTR, and average position.
  • Keyword Segmentation:
    • Head 1 to 3 words (broad intent / core commercial queries)
    • Long Tail 4+ words (high intent / specific queries)
  • Optional Sitemap Metric: Queries service.sitemaps().list() to display submitted vs indexed URL counts from submitted sitemaps for context.

Output Files

  • CSV: output/<site-url>/property-indexation-keyword-portfolio-<slug>-<start>-to-<end>.csv
  • HTML: output/<site-url>/property-indexation-keyword-portfolio-<slug>-<start>-to-<end>.html

Command-Line Interface

Terminal / Bash 
$python reports/property_indexation_keyword_report.py <site-url> --last-month --limit 250 --long-tail-threshold 4

3. Report 2: Question Queries Ranking Report

Script Location: reports/question_queries_report.py

Objectives and Classification Engine

  • Detection Logic: Matches 5W1H interrogative pronouns and adverbs (what, how, why, when, where, who, which), auxiliary question verbs (can, could, should, would, is, are, do, does, did, have, has), explicit question marks (?), and comparison patterns (difference between, versus, vs).
  • Opportunity Tiers:
    • Top Performers: Average position ≤ 3.0 (featured snippet / AI Overview candidates).
    • Striking Distance: Positions 3.1 to 20.0 (actionable targets for content refreshes and FAQ schema).
    • High Demand, Low CTR: Above-average impressions with below-average CTR.
  • URL Mapping: Pinpoints the destination pages currently answering each question query to identify content cannibalisation or thin answers.

Output Files

  • CSV: output/<site-url>/question-queries-ranking-<slug>-<start>-to-<end>.csv
  • HTML: output/<site-url>/question-queries-ranking-<slug>-<start>-to-<end>.html

Command-Line Interface

Terminal / Bash 
$python reports/question_queries_report.py <site-url> --last-month --category how --striking-distance-only --limit 500

4. Copyable Implementation Prompt

Provide the prompt below to your assistant or CLI session to implement the complete reporting pipeline.

# Task: Implement Property Indexation, Keyword Breadth, and Question Ranking Reports

Implement two new modular reports in the gsc-exporter codebase to analyse indexation depth, keyword portfolio distribution (head vs long tail), and question search queries.

## 1. Context and Codebase Architecture

Review the existing repository architecture before implementation:
- core/client.py: Provides GSC API authentication via get_gsc_service() and site listing via get_available_properties().
- core/cache.py: Provides fetch_with_cache(service, site_url, start_date, end_date, dimensions, ...) with monthly chunk fragmentation.
- core/naming.py: Standardises output directories using dot-notation (get_output_dir(site_url)) and output file slugs using hyphens (get_filename_slug(site_url)).
- core/date_utils.py: Provides parse_standard_date_args(args, service, site_url) handling --start-date, --end-date, and --last-month.
- reports/: Houses modular reports following the standard run_report(service, site_url, ...) signature.
- interactive-runner.py: Discovers and launches reports interactively.
- utilities/validate_all_reports.py: Runs automated sanity checks across reports.

Strict conventions to observe:
- British English throughout all code comments, docstrings, documentation, and user-facing text (e.g. analyse, categorise, prioritisation, behaviour).
- Do not use em dashes anywhere (use colons, semicolons, parentheses, or commas instead).
- Output files must be hyphen-separated, all lowercase, and SEO-friendly.
- Python module names in reports/ must be lowercase with underscores.
- Each report execution must produce at least one CSV file and one interactive HTML report using Bootstrap 5.
- Console output must print the explicit file paths (including file:// URIs).

## 2. Report 1: Property Indexation and Keyword Breadth Report
- Script: reports/property_indexation_keyword_report.py
- Objectives:
  1. Measure total active ranking/indexed URLs for the specified property and date range.
  2. Calculate total unique keywords ranking across the entire property.
  3. Calculate unique keywords ranking per URL.
  4. Segment keywords into Head (1 to 3 words) and Long Tail (4+ words).
  5. Optionally query service.sitemaps().list() to show submitted vs indexed counts from sitemaps.
- Outputs:
  - CSV: output/<site-url>/property-indexation-keyword-portfolio-<slug>-<start>-to-<end>.csv
  - HTML: output/<site-url>/property-indexation-keyword-portfolio-<slug>-<start>-to-<end>.html

## 3. Report 2: Question Queries Ranking Report
- Script: reports/question_queries_report.py
- Objectives:
  1. Identify all queries matching interrogative patterns (what, how, why, when, where, who, which, can, is, do, does, ?).
  2. Categorise questions by interrogative type and rank tier (top performers vs striking distance positions 4-20).
  3. Map questions to destination URLs.
- Outputs:
  - CSV: output/<site-url>/question-queries-ranking-<slug>-<start>-to-<end>.csv
  - HTML: output/<site-url>/question-queries-ranking-<slug>-<start>-to-<end>.html

## 4. Integration & Validation
- Register both reports in interactive-runner.py and utilities/validate_all_reports.py.
- Create unit tests for word counting and question regex matching in tests/.
