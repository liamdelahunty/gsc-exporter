How to Run the Monthly Summary Report Account-Wide

Learn how to execute the Monthly Summary Report across your entire Google Search Console portfolio, consolidating high-level performance metrics into a single unified executive dashboard and CSV extract.

1 Overview & Output Architecture

The reports/monthly_summary_report.py script is designed to operate in two distinct modes depending on how many properties are supplied:

  • Single Property Mode: When passed a single URL or domain (e.g. sc-domain:example.com), the report generates a single-site summary stored in output/<domain-slug>/.
  • Account-Wide Portfolio Mode: When executed with multiple properties (via --account-wide or --sites-file), the script queries each property, extracts performance totals and footprint dimensions, sorts them hierarchically, and aggregates everything into an account-level summary table.
Generated Output Locations (Account-Wide Mode):
All account-wide outputs are saved directly to the dedicated output/account/ directory:
  • HTML Dashboard: output/account/monthly-summary-report-account-wide-[START-DATE]-to-[END-DATE].html
  • Raw Metrics CSV: output/account/monthly-summary-report-account-wide-[START-DATE]-to-[END-DATE].csv

2 Execution Methods

There are two primary ways to run an account-wide report across your Google Search Console portfolio:

Method A: Automated Discovery (--account-wide / --all-sites)

This is the quickest method. It communicates with the Google Search Console API, dynamically retrieves every property your credentials have access to, and compiles the portfolio summary automatically. 

# Run for the last complete calendar month across all accessible properties
python reports/monthly_summary_report.py --account-wide --last-month

# Run for a custom date range across all accessible properties
python reports/monthly_summary_report.py --account-wide --start-date 2026-10-01 --end-date 2026-10-31

Method B: Curated Portfolio List (--sites-file)

Use this method when you want to report on a specific group of core sites or exclude secondary staging and test properties. Site URLs are supplied via a plain text file, one per line (lines beginning with # are treated as comments). 

# Run for a curated site list for the last complete calendar month
python reports/monthly_summary_report.py --sites-file site-lists/sites.txt --last-month

# Run for a custom curated list (e.g. core commercial properties)
python reports/monthly_summary_report.py --sites-file site-lists/core.txt --last-month

3 CLI Flags & Date Selection

The report conforms to the standardised GSC Exporter CLI parameter interface:

Argument / Flag Description Example
--account-wide / --all-sites Automatically queries all properties in the GSC account. --account-wide
--sites-file <path> Specifies a text file containing target site URLs, one per line. --sites-file site-lists/sites.txt
--last-month Calculates and analyses the last complete calendar month (recommended for monthly close). --last-month
--start-date YYYY-MM-DD Explicit start date for the reporting interval. --start-date 2026-09-01
--end-date YYYY-MM-DD Explicit end date for the reporting interval. --end-date 2026-09-30
--last-7-days Calculates and runs for the trailing 7 days of available data. --last-7-days
--branding-config <path> Optional custom branding JSON file for header logo, colours, and support links. --branding-config config/branding.json

4 Portfolio Metrics Included in the Table

For every property processed, the report extracts and calculates the following key performance indicators:

Column Header Data Source Description
Property GSC Site URL The canonical property identifier (e.g. sc-domain:croneri.co.uk or https://app.croneri.co.uk/).
Total Clicks Overall Site Query Total volume of user clicks from organic Google Search results.
Impressions Overall Site Query Total organic search appearances across all queries and pages.
CTR Calculated Overall Click-Through Rate (Total Clicks / Impressions).
Avg. Position Overall Site Query Average ranking position across all organic query appearances.
# Queries ['query'] dimension Number of distinct search queries that generated impressions for the property.
# Pages ['page'] dimension Number of distinct landing URLs that received organic visibility.

Hierarchical Sorting: The generated table orders rows by root domain, prioritizing Domain properties (sc-domain:) first, followed by primary www. properties, then subdomains, sorted by total clicks descending.

5 Recommended Operational Workflow

To ensure optimal execution speed and avoid repeated network calls to Google APIs, follow this standard three-step workflow:

  1. Inspect or Refresh Available Domains (Optional):
    Verify the list of sites associated with your Google credentials: 
    python utilities/show_available_domains.py > site-lists/available-domains.txt
  2. Warm the Cache (Recommended):
    Prime local monthly cache chunks before running the summary report. This fetches data in chunks and stores them locally in cache/: 
    python utilities/cache_warmer.py --file site-lists/sites.txt
  3. Generate the Account-Wide Summary:
    Execute the monthly summary report across all sites: 
    python reports/monthly_summary_report.py --sites-file site-lists/sites.txt --last-month
    Or run across the whole account dynamically: 
    python reports/monthly_summary_report.py --account-wide --last-month
  4. Review and Distribute:
    Open the generated HTML dashboard in your browser or attach the CSV file to your monthly stakeholder performance pack.

6 Troubleshooting & Tips

Authentication Check:
If authentication fails or tokens expire, delete config/token.json and re-run. A local browser window will open to authorize access via Google OAuth.
  • Handling Comments in Site Lists: Ensure any custom site list files prefix comments with #. The parser automatically ignores comment lines and blank lines.
  • High API Latency: Generating footprint metrics (# Queries and # Pages) requires two dimension queries per site. Priming the cache via utilities/cache_warmer.py drastically reduces execution time.
