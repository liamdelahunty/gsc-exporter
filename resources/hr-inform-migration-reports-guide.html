HR-Inform Migration Reports Guide

A complete operational guide for executing, analysing, and interpreting the Google Search Console (GSC) migration reports during the transition from legacy Drupal to DatoCMS on www.hr-inform.co.uk.

Migration Objective: Protect organic traffic, discover ranking opportunities, audit semantic search disconnects, and compile comprehensive 301 redirection maps as content transitions from legacy Drupal URLs into DatoCMS.

1. Migration Architecture & Overview

The migration suite for HR-Inform consists of six dedicated analytical scripts and a unified dashboard index generator, located in reports/migrations/. Each script serves a distinct role across the migration lifecycle:

Script Name Primary Purpose Key Deliverable
drupal_dato_migration_analysis.py Platform breakdown dashboard and query classification Platform traffic split (% Dato vs Drupal) & query-level mapping
drupal_dato_migration_prioritisation_report.py Identifies top 50 Drupal pages by traffic with SEO disconnect audits Prioritised content backlog capturing >68% of legacy traffic
drupal_dato_migration_page_level_report.py Unfiltered census of all legacy URLs receiving clicks Complete 301 redirection master list (bypassing privacy filters)
dato_suggested_urls_alphabetical_report.py Alphabetical catalogue of suggested Dato target paths Standardised kebab-case URLs with click-to-copy helpers
drupal_dato_gsc_comparison_report.py Quantifies GSC privacy loss and audits directory hierarchies Evaluation of hidden search traffic & directory-level volume
dato_pages_performance_report.py Organic performance tracking for live DatoCMS pages Post-launch visibility validation and keyword traction
generate_migration_index.py Unified HTML portal linking all reports and CSV datasets Executive navigation dashboard with live asset availability badges

2. How to Run the Reports

Prerequisites

  • Authenticated GSC credentials (configured via config/client_secret.json and cached tokens).
  • Access to the Google Search Console property for https://www.hr-inform.co.uk/ or sc-domain:hr-inform.co.uk.

Execution Workflow

For the most efficient execution, run the reports in the following sequential order:

1 Base Migration Analysis

Runs the core classification engine and generates the base CSV dataset. Subsequent prioritisation and alphabetical reports rely on this dataset. 

python reports/migrations/drupal_dato_migration_analysis.py https://www.hr-inform.co.uk/ --last-month

Typical runtime: 15-30 seconds (cached afterwards).

2 Top 50 Prioritisation Report

Audits the top 50 legacy URLs driving organic traffic, checking for semantic disconnects between page titles and user search intent. 

python reports/migrations/drupal_dato_migration_prioritisation_report.py https://www.hr-inform.co.uk/ --last-month

3 Unfiltered Page-Level Report (Redirection Census)

Extracts unfiltered page-level traffic data without query privacy stripping. 

python reports/migrations/drupal_dato_migration_page_level_report.py https://www.hr-inform.co.uk/ --last-month

4 Alphabetical Proposed URLs Catalogue

Generates the alphabetical catalogue of programmatic Dato target paths with one-click copy buttons. 

python reports/migrations/dato_suggested_urls_alphabetical_report.py https://www.hr-inform.co.uk/ --last-month

5 GSC Comparison & Directory Audit

Compares page-level and query-level datasets to quantify privacy filtering and maps legacy directories. 

python reports/migrations/drupal_dato_gsc_comparison_report.py https://www.hr-inform.co.uk/ --last-month

6 DatoCMS Pages Performance

Evaluates the organic health and search rankings of pages already migrated to DatoCMS. 

python reports/migrations/dato_pages_performance_report.py https://www.hr-inform.co.uk/ --last-month

7 Generate the Migration Index Dashboard

Compiles an executive HTML landing page linking all generated reports with status indicators. 

python reports/migrations/generate_migration_index.py https://www.hr-inform.co.uk/ --last-month

Standard Command-Line Arguments

  • site_url: Optional positional argument. Defaults to https://www.hr-inform.co.uk.
  • --last-month: Automatically resolves the start and end date to the most recent completed calendar month.
  • --last-7-days: Runs the analysis over the last 7 full days of recorded data.
  • --start-date YYYY-MM-DD & --end-date YYYY-MM-DD: Custom analysis window.
  • --limit <int>: Controls the maximum number of rows rendered in the HTML table (default is typically 100).
  • --queries-limit <int>: Number of top driving queries displayed per page in expandable drawers (default: 5).

3. How to Read and Interpret the Results

A. Platform Breakdown Dashboard (Query-Level)

Primary Question Answered: What proportion of our search traffic has successfully migrated to DatoCMS?

  • Migration Progress Metric: Displays total clicks and impressions attributed to Dato URLs versus Drupal URLs. A rising Dato share indicates successful indexation and transition.
  • Query Platform Breakdown: Demonstrates whether top organic keywords are triggering old Drupal URLs or new Dato URLs. If a primary revenue keyword triggers an old Drupal page, prioritise that page for content migration.
  • CTR & Average Position Comparisons: Compare the click-through rates and average positions between legacy pages and newly migrated pages to ensure search visibility is maintained or improved.
B. Top 50 Prioritisation Report

Primary Question Answered: Which legacy pages must be migrated next to protect our core traffic?

  • Pareto Principle (>68% Traffic Rule): Typically, the top 50 legacy URLs account for over two-thirds of total organic Drupal clicks. Migrating these 50 pages delivers maximum risk reduction with minimum authoring effort.
  • SEO Semantic Disconnect Audit:
    • The report analyses the legacy URL slug against the primary user search queries driving clicks.
    • Warning Badge: Highlights when a legacy URL slug does not align with the actual keyword intent (e.g. legacy slug mentions "policy-update" but users search for "statutory sick pay calculation").
    • Use these flags to refine page headings and metadata in DatoCMS before publishing.
  • Proposed Dato URLs: Suggests clean, standardised target paths following modern URL naming guidelines.
C. Unfiltered Page-Level Report (Redirection Planning)

Primary Question Answered: Which URLs need 301 redirects to eliminate 404 crawl errors?

  • Unfiltered Data Integrity: Google Search Console applies privacy filtering to query-level data, dropping low-volume or sensitive queries. By requesting only the ['page'] dimension, this report captures 100% of organic clicks.
  • Master 301 Mapping Inventory: Every URL appearing in this report with 1 or more clicks has demonstrated real organic value. Content teams must map each URL to an equivalent Dato destination or appropriate category landing page.
  • CSV Export: Use the corresponding .csv export directly in redirection deployment tools (NGINX map files, Cloudflare Bulk Redirects, or DatoCMS URL routing rules).
D. GSC Data Comparison & Directory Audit

Primary Question Answered: How much traffic is hidden by GSC privacy thresholds, and which legacy site sections are largest?

  • The Privacy Gap: Calculates the variance between unfiltered page clicks and query-attributed clicks. In technical B2B niches, this gap can exceed 30-40% of total clicks.
  • Directory Breakdown: Aggregates traffic by URL directory structures (e.g. /resources/, /employment-law/, /news/, /contracts/). This allows content managers to migrate entire thematic silos systematically rather than individual pages in isolation.
E. DatoCMS Pages Performance Report

Primary Question Answered: Are our newly launched DatoCMS pages ranking and capturing organic search demand?

  • Early Indexation Check: Confirms that newly published Dato URLs are appearing in Google Search.
  • Top Driving Queries: Displays the specific search terms users entered to reach the new Dato pages, confirming keyword alignment and snippet performance.
  • Ranking Trajectory: Identifies whether new URLs are retaining top 3 or page 1 positions previously held by Drupal counterparts.

4. Best Practice Migration Workflow

  1. Run Base Reports at the Start of Each Sprint: Generate the suite for the last complete calendar month to benchmark traffic.
  2. Assign the Top 50 Backlog: Hand the Prioritisation Report to copywriters and content editors. Resolve semantic disconnects during content entry in DatoCMS.
  3. Review Proposed Target Slugs: Always verify programmatic suggested URLs against brand guidelines and site hierarchy before setting them live.
  4. Deploy Redirection Maps: Export the Page-Level Report CSV and implement 301 redirects concurrently with DatoCMS page launches.
  5. Track Dato Visibility Weekly: Run the Dato Pages Performance report weekly using --last-7-days to catch indexing delays or ranking drops early.
